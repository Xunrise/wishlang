Usage first. Code second.

1 · wish

Write the calls you want

Types, methods and modules that do not exist yet. Your editor marks them as will be generated instead of red errors.

2 · prototype

Save, and skim the shape

Claude Code writes a mocked version you can read in a minute. The app restarts on every save, so you see each change run.

3 · implement

Make it real when you like it

One click turns the prototype into the real implementation. The project stays plain Rust or Java: no runtime, no macros.

You always know who wrote a line, and why.

The IntelliJ plugin, the Zed extension and the Neovim plugin tint everything Claude generated. Hover for the reason and the edit that triggered it. On a ticket branch, every change is traced to a problem of the ticket.

TintedGutter bar and a faint tint on generated code, stronger and italic while mocked.

Reasons on hoverWho wrote it, why, and which of your edits triggered it.

Traced to tickets◆ P1 · P2 lenses link code to the problems it serves.

Untraced is redGenerated code that serves no problem of the ticket stands out.

IntelliJ IDEA

✓ Java (Maven)

Tints, hovers and ticket lenses, plus the Wish tool window: the journal of every cycle with diffs and Claude's reasoning, and the ticket as a problem tree. Offers to download wishlang on first run.

Zed

✓ Rust

Runs next to rust-analyzer and colours generated code through semantic tokens. Downloads the wishlang binary itself when it is not on PATH.

Install from Zed extensions

Neovim

✓ Rust · Java

Lua plugin: semantic-token tint, hover reasons, code lenses for Implement and Accept/Reject, :WishLog and :WishTicket. Add the repo's nvim/ folder to your runtimepath.

Install in one line.

curl -fsSL https://raw.githubusercontent.com/Xunrise/wishlang/master/install.sh | sh
brew install Xunrise/tap/wishlang
irm https://raw.githubusercontent.com/Xunrise/wishlang/master/install.ps1 | iex
cargo install wishlang

Then run wishlang init in a Rust or Maven project. Needs Claude Code on PATH.
